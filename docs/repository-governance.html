Repository governance

The LydiaRX site is backed by DS specifications and shared repository rules. This page explains how public pages, technical pages, and the specification set must stay synchronized.

Source-of-truth model

AGENTS.md

Root guidance for future agents, reading order, current local skill catalog, runtime defaults, and key paths.

DS specifications

Authoritative contracts for vision, coding style, site architecture, visual system, delivery model, and content governance.

Technical pages

Browsable explanations of repository layout, project architecture, and update obligations.

Public pages

Branded LydiaRX narratives that must remain aligned with the constraints and claim boundaries defined in the DS set.

Required update behavior

When content changes

Update the affected public page and the matching DS file so positioning, structure, and claim boundaries remain aligned.

When structure changes

Update navigation, shared client-side helpers, partials, technical pages, and the relevant DS sections together rather than in isolated edits.

When style changes

Adjust `docs/styles.css`, confirm the visual system still matches DS003, and keep the site responsive across the page set.

Verification workflow

The project intentionally avoids a build pipeline. Verification is therefore performed through lightweight repository checks that confirm structure, links, matrix generation, and static delivery.

  • node .agents/skills/gamp_specs/scripts/generate_specs_matrix.mjs
  • node .agents/skills/gamp_specs/scripts/verify_docs_links.mjs
  • node .agents/skills/gamp_specs/scripts/verify_static_site.js docs --path / --path /project-architecture.html --path /specsLoader.html
  • ./fileSizesCheck.sh
